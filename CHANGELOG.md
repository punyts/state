# Changelog

## Unreleased
- **Write origin.** `set`, `delete`, `apply`, `applyIf` and `replace` take an optional last argument `{ origin }`, and `link` takes `origin` in its options. Every change event the write emits, the per-key events of a merge and the events passed on to aliases included, calls its listeners with the origin as a fifth argument. A write a listener makes while it is called is its own and is untagged; an untagged write calls listeners with the four arguments as before. State sync uses it to apply a server's changes without capturing and sending them back (AMM-1810).
- **A change above an alias target hands the alias its own values.** Writing a path above a target (`set` or `replace` of `$.data.totals` for an alias of `$.data.totals.month`) now calls the alias listeners with the values at the target's place, not the whole object of the changed path. A component bound to a linked number got the parent object as its last value and kept showing the old number.
- **A child change at an alias target reaches the alias path only.** An `insert-child`, `update-child` or `delete-child` at a target now reaches the alias path as it reaches the target path, and the child's own event reaches the path below the alias. Before, it reached every listener at and below the alias, so adding each row under a linked list re-ran every binding of the rows already there.
- **Cheaper reads through aliases.** The path a read resolves to and its segments are cached until the links change; the walk does one lookup per segment; proxy traps are made once per base path, and a proxy answers its raw object through a store-private symbol instead of a `WeakMap`.
- **Writes and links cost what they touch, not the size of the store.** Listener paths and link targets are kept in path indexes (`PathIndex`), so an emit finds the listeners at and below a path, the wildcards whose literal prefix leads to it, and the aliases whose target is at, below or above it, without visiting every listener and every link. Before, each write passed over every link (resolving each target) and each link or tree emit passed over every listener, so building many linked nodes grew with the square of the store. `link` no longer copies the link map. Listeners are still called in the order their paths were first listened to and aliases in the order they were made. A change now reaches an alias whose target leads through another alias by being passed on through that alias, as it already was for listeners below it.
- **Re-pointing reaches listeners behind several aliases.** Re-pointing an alias now notifies every listener whose resolved path changed, once, at any depth and arrangement of aliases, including a listener below an alias that leads to another alias below the re-pointed one (for example a view alias over a holder whose child is linked through the re-pointed alias). A change at the new target reaches those listeners too.

## 1.2.0
- **Store links.** `store.link(from, to)` makes a path an alias of another; reads and writes at or below the alias act on the target, changes at, above or inside the target notify the alias listeners, and aliases never appear in `store.get('$')` snapshots. `store.unlink(from)` removes it (AMM-1639).
- **Re-pointing, chains, `allowMissing` and `protect`.** `link` on an existing alias re-points it and notifies every listener at or below it, and on every alias that resolves through it, once. `link(from, to, { allowMissing: true })` accepts a target that does not exist yet. `store.protect(path)` / `store.unprotect(path)` make a path read-only, also through aliases (AMM-1642).

## 1.1.0
- Array mutators through proxies produce the same array as on a plain array and emit on the array path (AMM-1584).
